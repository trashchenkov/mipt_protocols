- [Блокнот](protocols.ipynb): MCP (90 минут), продолжение A2A/AG-UI/A2UI/ACP и коммерческие протоколы (60 минут), дополнительный раздел Skills.

## Самостоятельное изучение

Начните с установки и общей настройки в § 1 блокнота. Затем выполняйте ячейки сверху вниз:
каждый пример использует результаты предыдущих шагов. Номер раздела внизу слайда показывает,
где находятся полный код и пояснения. В § 17 есть контрольные вопросы с раскрываемыми ответами.
Домашнее задание вынесено в отдельный PDF; раздел Skills изучается дополнительно.

Структура QR-навыка:

```text
skills/
└── qr-code/
    ├── SKILL.md
    └── scripts/
        ├── qr_generate.py
        └── qr_read.py
```

Имя папки `qr-code` совпадает с `name` в YAML файла `SKILL.md`.
`references/` и `assets/` добавляются, когда у навыка есть справочники или шаблоны.
Параметр `skills` в `create_deep_agent` подключает штатный `SkillsMiddleware`: он обнаруживает навыки,
а агент читает выбранный `SKILL.md` через `read_file`. В локальном примере файловые инструменты и shell используют реальные пути.
Формат описан в [Agent Skills](https://agentskills.io/specification) и [подключению навыков Deep Agents](https://docs.langchain.com/oss/python/deepagents/skills).

## Установка и настройка

Настройка одна для всех разделов блокнота. Нужны доступ в интернет, uv и ключ GigaChat API.
Все команды ниже выполняются в терминале; на Windows можно использовать PowerShell.

### 1. Установите uv и скачайте материалы

Если uv уже установлен после занятия по RAG, проверьте его командой `uv --version` и переходите к скачиванию.
В остальных случаях установите его по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).

macOS / Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

После установки откройте новый терминал и выполните `uv --version`.

Если установлен Git, скачайте репозиторий:

```bash
git clone https://github.com/trashchenkov/mipt_protocols.git
cd mipt_protocols
```

Без Git откройте [репозиторий на GitHub](https://github.com/trashchenkov/mipt_protocols), выберите
**Code → Download ZIP**, распакуйте его и откройте терминал в распакованной папке.
Далее работайте в папке, где лежат `protocols.ipynb`, `pyproject.toml`, `uv.lock` и `.env.example`.

### 2. Установите зависимости

```bash
uv sync --locked
```

uv подберёт Python 3.12 и создаст окружение `.venv` с точными версиями библиотек из `uv.lock`.
Отдельно устанавливать Python, запускать `pip install` и активировать `.venv` не нужно:
в следующих командах `uv run` использует окружение проекта.
Даже если вы прошли RAG, здесь нужно своё окружение: набор библиотек другой.
Для первого запуска дождитесь окончания загрузки и установки пакетов.

### 3. Создайте и заполните `.env`

В репозитории есть шаблон [`.env.example`](.env.example). Файл `.env` с вашим ключом создаётся локально
в той же папке, что и `lab.py`. Если `.env` уже заполнен, пропустите копирование, чтобы не затереть настройки.

macOS / Linux:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

В Windows cmd вместо этого используйте `copy .env.example .env`.
Откройте `.env` в текстовом редакторе; на Windows проверьте, что файл не получил расширение `.env.txt`.
Файлы с точкой в начале имени могут быть скрыты в файловом менеджере и Jupyter.

Получите ключ в [кабинете GigaChat API](https://developers.sber.ru/studio/workspaces/my-space/get/gigachat-api):
откройте проект GigaChat API, перейдите в настройки API и получите ключ авторизации.
Впишите его после `GIGACHAT_CREDENTIALS=`. Если у вас уже есть действующий ключ после RAG, можно использовать его.
Нужен **ключ авторизации**, а не временный `access_token`; обмен ключа на токен выполняет SDK.

```dotenv
GIGACHAT_CREDENTIALS=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
GIGACHAT_VERIFY_SSL_CERTS=False
```

Замените `ваш_ключ_авторизации` настоящим значением. Остальные строки скопированы из шаблона:

| Переменная | Что задаёт |
|---|---|
| `GIGACHAT_CREDENTIALS` | Ключ авторизации вашего API-проекта; обязательный параметр для модельных примеров |
| `GIGACHAT_SCOPE` | Тип доступа: `GIGACHAT_API_PERS` для физических лиц; `GIGACHAT_API_B2B` для бизнес-пакетов; `GIGACHAT_API_CORP` для бизнес-доступа pay-as-you-go. Значение должно соответствовать вашему проекту |
| `GIGACHAT_MODEL` | Модель для примеров; в шаблоне `GigaChat-3-Ultra`. Нужен доступ к выбранной модели в вашем API-проекте |
| `GIGACHAT_VERIFY_SSL_CERTS` | Проверка TLS-сертификатов. В учебном шаблоне `False` отключает её; для работы с проверкой настройте доверенные сертификаты и задайте `True` |

Подробнее: [авторизация GigaChat API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)
и [Python SDK, включая настройку сертификатов](https://github.com/ai-forever/gigachat).

Сохраните файл. Настройки загружаются из `.env` при импорте `lab`; вручную выполнять `export` или задавать
переменные через PowerShell не нужно. Если изменили файл после запуска ячеек, перезапустите ядро Jupyter
и снова выполните общую настройку из § 1. Уже заданные переменные процесса могут иметь приоритет над `.env`.
Файл `.env` исключён из Git; ключ не нужно вставлять в ячейки и публиковать вместе с работой.

### 4. Проверьте окружение

```bash
uv run python tools/check_env.py
```

Скрипт показывает версию Python и библиотек, проверяет импорты и наличие ключа без вывода его значения.
Ожидаемый результат: Python 3.12, строка `GigaChat: ключ задан` и сообщение о завершении проверки.
Если написано `заполните .env`, вернитесь к шагу 3.
Проверка не обращается к API: она не подтверждает действительность ключа, доступ к модели и остаток квоты.
Модельные ячейки блокнота делают реальные запросы и расходуют квоту GigaChat API.

Для публичных примеров Туту и ВкусВилла отдельные ключи не нужны. Вход в личный кабинет ВкусВилла
обсуждается отдельно и для основного опыта не выполняется. Для дополнительного QR-примера
установите ZBar по [инструкции ниже](#skills-qr-коды-на-разных-ос) и выполните проверку с `--qr`.

### 5. Откройте блокнот с ядром проекта

Один раз зарегистрируйте ядро из окружения проекта:

```bash
uv run python -m ipykernel install --user --name mipt-protocols --display-name "Python (mipt-protocols)"
```

Затем запустите Jupyter из этой же папки:

```bash
uv run jupyter lab protocols.ipynb
```

В блокноте выберите **Kernel → Change Kernel → Python (mipt-protocols)**.
При работе в VS Code выберите интерпретатор `.venv` этой папки через **Select Kernel**.
Если вы переместили папку проекта, повторите регистрацию ядра по новому пути.
Окно терминала с Jupyter оставьте открытым на время работы.

Выполните первую ячейку с кодом из § 1: она показывает Python 3.12, дату поездки, модель и `Ключ задан: True`.
Затем запускайте ячейки сверху вниз. После перезапуска ядра сначала повторите § 1,
даже если продолжаете с A2A или интерфейсных протоколов.
Серверы для примеров запускаются из ячеек; отдельно вводить команды их запуска не требуется.

### Если запуск не получился

| Сообщение или ситуация | Что проверить |
|---|---|
| `uv` не найден | Откройте новый терминал после установки и проверьте `uv --version` |
| `ModuleNotFoundError` или другая версия Python | Выполните `uv sync --locked`, выберите ядро `Python (mipt-protocols)` и перезапустите его |
| `Ключ задан: False` | Наличие `.env` рядом с `lab.py`, точное имя файла и заполненную строку `GIGACHAT_CREDENTIALS` |
| Ошибка авторизации GigaChat | Ключ авторизации и scope одного проекта; не подставлен ли временный токен вместо ключа |
| После изменения `.env` используются прежние настройки | Перезапустите ядро и выполните § 1; проверьте, не заданы ли эти переменные в среде запуска Jupyter |
| Ошибка загрузки ZBar | Для дополнительного QR-раздела выполните установку для своей ОС по таблице ниже |

Основная часть занятия не требует нативного декодера. Для дополнительного QR-примера нужен ZBar:

| ОС | Дополнение к `uv sync` |

```bash

```

Она создаёт QR и читает его обратно. Включённый `qr_read.py` на macOS настраивает поиск библиотек Homebrew для Python из uv.
Установка DLL описана в [документации pyzbar](https://github.com/NaturalHistoryMuseum/pyzbar#installation).
Если проверка сообщает об ошибке загрузки ZBar, установите системную библиотеку или Runtime для своей ОС по таблице выше.

## Серверы и повторный запуск

Ячейки сами запускают дочерние процессы и проверяют их готовность. Используются локальные порты:
8765 — MCP, 9100 — A2A SDK, 9300 — Agent Server, 9200/9201 — AG-UI/A2UI.
Если порт занят посторонним процессом, в блокноте появляется сообщение об этом. Повторный запуск своего сервера останавливает его прежний экземпляр.
В конце разделов есть ячейки остановки; общая команда — `lab.stop_all()`.
Журналы и временные файлы находятся в `.runtime/` и исключены из Git.

Агент обращается к публичным серверам Туту и ВкусВилла. Дата поездки вычисляется относительно дня запуска.
Цены и результаты могут меняться. Выполняйте модельные примеры последовательно: API может ограничивать параллельные запросы.
Создание ссылки на корзину не оформляет заказ. Вход в личный кабинет и платёжные операции в примерах не выполняются.

В § 16 разобраны этапы покупки, коммерческие ACP и UCP, полномочия AP2, оплата HTTP-доступа через x402,
российский YCP и границы возможностей Туту и ВкусВилла. Три учебные ситуации показывают разрешённую покупку,
превышение бюджета и потерю ответа на платёжный запрос. Платёжные запросы в этом разделе не отправляются;
условные данные не являются сообщениями конкретного протокола. Сведения о внедрениях проверены на 12 ноября 2026 года.

## ACP: исправление кода с разрешениями

В § 15 блокнот копирует два файла из `data/acp_project/` в `.runtime/acp-workspace`.
В исходном расчёте стоимости не учитывается количество продуктов; два из четырёх тестов ожидаемо падают.
Агент сначала анализирует проект без изменений, затем в той же ACP-сессии исправляет код и запускает тесты.
Блокнот показывает уведомления `session/update` и запросы `session/request_permission`.
На каждый запрос введите `y`, чтобы разрешить действие один раз, или Enter, чтобы отклонить.
Решения принимаются клиентом; без обработчика разрешений `ACPClient` отклоняет действия.

Файлы и команды выполняет агент через LocalShellBackend, а не через файловые или терминальные ACP-методы клиента.
Для полного результата разрешите правку учебного файла и команду unittest, показанную на экране.
После завершения блокнот независимо запускает четыре теста и проверяет, что исходный файл тестов не изменён.
При отказе действие не обходится автоматической проверкой. Повторный запуск подготовительной ячейки восстанавливает два исходных файла.

## Два способа A2A

`servers/a2a_sdk.py` публикует `agents.travel.travel_graph` через a2a-sdk.
`servers/agent_server.py` передаёт ту же фабрику в LangGraph Agent Server.
Общий клиент показывает JSON-RPC, завершённую задачу и artifact. Он также используется координатором с MCP ВкусВилла.


## Домашнее задание

Условия находятся в [homework_mcp_knowledge_base.pdf](homework_mcp_knowledge_base.pdf).
Подготовьте собственный корпус и RAG-индекс, подключите готовый MCP-сервер поиска к агенту
и верните top-k фрагментов с идентификаторами источников. Проверьте поиск на 15–20 запросах,
дайте ручную оценку и приложите инструкцию воспроизведения.
Эмбеддинги документов и запросов вычисляются локально. В примере Qdrant используется FastEmbed
с моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; она задаётся через `EMBEDDING_MODEL`.
Дополнительно по желанию: передайте найденные top-k фрагменты и исходный вопрос в LLM, получите ответ на вопрос со ссылками на источники.

В PDF приведены критерии оценки, состав сдачи и пример запуска Qdrant с `MCPAdapter` и Deep Agents.
Для этого примера используйте указанный git-коммит и отдельное окружение сервера:
пакет `mcp-server-qdrant==0.8.1` из PyPI имеет другие зависимости.
